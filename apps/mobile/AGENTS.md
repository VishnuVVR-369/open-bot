# apps/mobile

The Expo (React Native) Android app: a pocket inbox, chats, approvals, the computer viewer and the phone connection.
It talks to the deployment through the oRPC contract in `packages/api` and does not import web code.
Setup, usage, release builds and device tests are in `apps/mobile/README.md`; this file does not repeat them.
The native phone-egress code is here, but the tunnel protocol itself belongs in `packages/egress`.

## Entry points

- `apps/mobile/index.ts` is the JS entry; routes live in `apps/mobile/src/app` (expo-router).
- `apps/mobile/app.config.ts` is the Expo config and picks the variant (`APP_VARIANT`).
- `apps/mobile/modules/egress`, `passkey`, `share-intent` and `sms-consent` are the native modules.
- `apps/mobile/modules/egress/core` is the Kotlin tunnel core.
- `apps/mobile/src/computer/viewer.ts` is the noVNC viewer, bundled into `apps/mobile/src/computer/viewer-html.ts`.
- `apps/mobile/plugins` holds the Expo config plugins.

## Layout

Feature logic, hooks, tests and components live under `apps/mobile/src/features/<feature>/`.
Expo Router routes in `src/app` re-export the feature screens; navigation layouts stay there.
`src/lib` and `src/components` hold shared client and UI infrastructure.

## Invariants

- `apps/mobile/src/computer/viewer-html.ts` is generated by `pnpm --filter @open-bot/mobile build:viewer`; never edit it.
- Run `pnpm --filter @open-bot/mobile build:viewer` after changing `viewer.ts` or `@novnc/novnc`; CI fails when the generated file is stale (`check:viewer`).
- Do not import `@open-bot/domain/server` (Node-only: tokens, secrets, page links) here; lint enforces it.
- Egress test vectors in `packages/egress/test-vectors` are shared with the Kotlin core, which CI runs with `./gradlew test`.
- The merged Android manifest must pass `apps/mobile/scripts/check-egress-manifest.mjs` for both variants.
- Release builds need the Android checks from the openbot-mobile skill; debug success proves little.
- Mobile renders agent tools generically, so a new tool needs no change here.

## Recipes

Paths are relative to the repo root; symbols are in parentheses.

### Add a mobile screen

1. A file in `apps/mobile/src/app/` plus its `Tabs.Screen` in `(tabs)/_layout.tsx` or `Stack.Screen` in `_layout.tsx`.
2. Data: a view in `packages/api/src/views.ts`, a procedure in `packages/api/src/contracts/<feature>.ts` (composed in `packages/api/src/contract.ts`), its handler in the web feature's `server/routes.ts` (`apps/web/src/features/<feature>/server/routes.ts`, mounted in `apps/web/src/lib/server/api/router.ts`), a hook in `apps/mobile/src/lib/queries.ts` and a procedure-path key in `apps/mobile/src/lib/query.ts`. Event refreshes come from `APP_EVENT_REFRESHES` in `packages/api/src/events.ts`.
3. Search entry in `apps/mobile/src/app/search.tsx` (`PAGES`); notification links in `apps/mobile/src/lib/links.ts` and the worker's `nativeUrl()` in `apps/worker/src/features/notifications/fcm.ts`.

## Tests

- Unit: `pnpm --filter @open-bot/mobile test` (vitest, Node, `src/**/*.test.ts`).
- Types: `pnpm --filter @open-bot/mobile typecheck`; Expo health: `pnpm --filter @open-bot/mobile doctor`.
- Kotlin core: `./gradlew test` in `apps/mobile/modules/egress/core`.
- Device flows: `pnpm test:mobile-ui` and the Maestro flows in `apps/mobile/maestro`.
- Pocket inbox: `pnpm test:pocket-inbox` and `pnpm test:integration` (`apps/worker/src/features/notifications/fcm.integration.test.ts`, `apps/worker/src/features/uploads/service.integration.test.ts`).
- Built artifact: follow `apps/mobile/README.md` for local builds and release checks. CI coverage and skip rules are in [Android CI](../site/src/app/docs/development/page.mdx#android-ci).
