# Configuration

open-bot is configured with environment variables.
In development, the web app, the worker and the pages service all read the repository's root `.env`, copied from `.env.example`.
Every value has a development default except `OWNER_EMAIL`.
`BETTER_AUTH_SECRET` is the one exception in the code: it has no default, so `.env.example` supplies a placeholder, which production refuses.
The variables for tests and tooling are listed apart, under [Test and tooling variables](#test-and-tooling-variables).
Each app reads the environment in one module, listed in `scripts/lint/env-modules.mjs`, and packages take their settings as arguments; lint refuses `process.env` anywhere else outside tests and scripts.

<Callout kind="warning">
  The defaults for `BETTER_AUTH_SECRET`, `WORKER_SECRET`, `BOTD_TOKEN`, `ENCRYPTION_KEY` and
  `PAGES_SECRET` are public. Replace every one of them in any deployment. See
  [Deployment](/docs/deployment#1-secrets).
</Callout>

## Shared secrets

| Variable         | Web | Worker | Computer | Pages | Notes                                                                                 |
| ---------------- | --- | ------ | -------- | ----- | ------------------------------------------------------------------------------------- |
| `DATABASE_URL`   | yes | yes    |          | yes   | Default `postgres://openbot:openbot@127.0.0.1:54329/openbot`                          |
| `WORKER_SECRET`  | yes | yes    |          |       | At least 16 characters. Authenticates internal calls and signs VNC and egress tokens. |
| `ENCRYPTION_KEY` | yes | yes    |          |       | 32 bytes, base64. Encrypts every stored secret with AES-256-GCM.                      |
| `BOTD_TOKEN`     |     | yes    | yes      |       | At least 16 characters. botd refuses to start without it.                             |
| `PAGES_SECRET`   | yes |        |          | yes   | At least 32 characters. Signs and verifies the 10 minute links to pages.              |

## Worker

Parsed with zod in `apps/worker/src/env.ts`.
`DATABASE_URL`, `WORKER_SECRET`, `ENCRYPTION_KEY` and `BOTD_TOKEN` are the [shared secrets](#shared-secrets) above, and the worker also reads the [memory AI](#memory-ai) variables.

| Variable                     | Default                                       | Purpose                                                                                                                    |
| ---------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `WORKER_PORT`                | `4001`                                        | HTTP and websocket port                                                                                                    |
| `BOTD_URL`                   | `http://127.0.0.1:7070`                       | Where botd listens. Locally, Compose maps it from port 7000.                                                               |
| `APP_URL`                    | `BETTER_AUTH_URL`, or `http://localhost:3000` | Webhook URLs start with it                                                                                                 |
| `MAX_CONCURRENT_RUNS`        | `4`                                           | Runs executing at once, across all teammates                                                                               |
| `WATCH_ALLOW_PRIVATE_URLS`   | `false` in production, `true` otherwise       | Let page watches fetch private and local addresses                                                                         |
| `HOST_CODEX_AUTH_FILE`       | `~/.codex/auth.json`                          | Development: the login the computer borrows. Give an absolute path: `~` is not expanded.                                   |
| `HOST_CODEX_BIN`             | `codex`                                       | Development: the Codex CLI used to refresh that login                                                                      |
| `OPENAI_API_BASE_URL`        | `https://api.openai.com/v1`                   | Where API key traffic goes: the OpenAI API, or a compatible proxy                                                          |
| `COMPUTER_LIFECYCLE_ENABLED` | `false`                                       | Let the computer sleep when idle and wake on demand. Set the same value on the computer.                                   |
| `COMPUTER_IDLE_MINUTES`      | `5`                                           | With the lifecycle on: minutes without work before the computer goes to sleep. Above 0, at most 60.                        |
| `FCM_SERVICE_ACCOUNT_JSON`   | unset                                         | The Firebase service account JSON, on one line, used to send phone notifications. Without it, phones get no notifications. |

### Memory AI

Optional, and off unless the URLs are set.
Read by the worker, through `memoryAIConfig` in `packages/memory/src/jobs.ts`.
See [Memory](/docs/flows/memory#optional-ai).

| Variable                        | Default | Purpose                                                  |
| ------------------------------- | ------- | -------------------------------------------------------- |
| `MEMORY_EMBEDDING_URL`          | empty   | An OpenAI-compatible `/embeddings` URL                   |
| `MEMORY_EMBEDDING_MODEL`        | empty   | The embedding model                                      |
| `MEMORY_EMBEDDING_DIMENSIONS`   | `768`   | Vector size, 1 to 4096                                   |
| `MEMORY_SEMANTIC_MAX_DISTANCE`  | `0.4`   | The cosine-distance cutoff for semantic matches, 0 to 2  |
| `MEMORY_EXTRACTION_URL`         | empty   | An OpenAI-compatible `/chat/completions` URL             |
| `MEMORY_EXTRACTION_MODEL`       | empty   | The extraction model                                     |
| `MEMORY_AI_API_KEY`             | empty   | A bearer token for those two endpoints only              |
| `MEMORY_AI_DAILY_REQUEST_LIMIT` | `100`   | All memory AI requests per day. `0` turns memory AI off. |

## Accounts

Gmail, Google Calendar and Notion need no environment variables.
Your Google OAuth client is pasted into Settings, and Notion's client registers itself on the first connect.
See [Your accounts](/docs/flows/accounts#setting-up-google).

The redirect URIs are built from `BETTER_AUTH_URL`, the app's public URL:

```text title="Redirect URIs"
<BETTER_AUTH_URL>/api/accounts/google/callback
<BETTER_AUTH_URL>/api/accounts/notion/callback
```

The Google one goes in your OAuth client, and Settings shows it with a copy button.
If the app's URL changes, add the new URI to your Google client; the app registers with Notion again by itself for a new URI.

`GOOGLE_BASE_URL` and `NOTION_MCP_URL` exist for tests only, and are listed under [Stand-ins for outside services](#stand-ins-for-outside-services).

## Pages service

See [The pages service](/docs/architecture/pages).
Parsed in `apps/pages/src/env.ts`; the service refuses to start when a value is invalid.

| Variable                | Default                                                        | Purpose                                                                 |
| ----------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `PORT`                  | `3400`                                                         | HTTP port                                                               |
| `PAGES_URL`             | `https://$RAILWAY_PUBLIC_DOMAIN`, or `http://127.0.0.1:<PORT>` | Its own public URL, which the runtime and `/lib` addresses use          |
| `RAILWAY_PUBLIC_DOMAIN` | unset                                                          | Set by Railway. Builds `PAGES_URL` when that is not set.                |
| `APP_URL`               | `http://localhost:3000`                                        | The app's origins, comma-separated: the only ones that may frame a page |
| `PAGE_LIB_DIR`          | `dist/lib` next to the server, or the page kit's build         | Where `/lib` is served from                                             |

In production, the pages service and the web app refuse to start without a `PAGES_SECRET` of at least 32 characters, or with its public development default.

## The computer (botd)

The computer does not read the repository's `.env`.
Locally, `docker-compose.yml` passes it only `BOTD_TOKEN` and `APPLY_GUARD_EXTRA_DOMAINS` (taken from your shell or `.env` when set), so set any other variable below in a Compose override.
On Railway, set them on the `computer` service.
botd parses them in `apps/botd/src/env.ts` and refuses to start when one is invalid.

| Variable                     | Default                            | Purpose                                                                                                   |
| ---------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `BOTD_TOKEN`                 | none                               | Required, at least 16 characters. With `NODE_ENV=production`, not the public development token.           |
| `COMPUTER_LIFECYCLE_ENABLED` | `false`                            | The computer can sleep and wake. Also lowers the screen defaults below. Set the same value on the worker. |
| `MAX_SCREENS`                | `4`, or `2` with the lifecycle on  | Screens running at once                                                                                   |
| `SCREEN_IDLE_MINUTES`        | `20`, or `3` with the lifecycle on | A screen nobody used for this long stops                                                                  |
| `APPLY_GUARD_EXTRA_DOMAINS`  | empty                              | Comma-separated extra domains for the apply guard. Compose sets `host.docker.internal` for the tests.     |
| `BOTS_GID`                   | `1100`                             | The shared `bots` group, set in the image                                                                 |
| `PAGE_LIB_DIR`               | `/opt/page-kit/lib`                | Where the page preview server serves `/lib` from. The image copies the page kit there.                    |

botd's own ports are fixed: 7000 for its API, 4500 for Codex (localhost), 1080 for SOCKS (localhost) and 7080 for the page preview server (localhost).
The Codex version is the image's `CODEX_VERSION` build argument.
botd sets `OPEN_BOT_CHROMIUM_ARGS` itself for each screen's browser, and `/etc/chromium.d/open-bot` reads it.
It is not a setting.

## Standard variables

`NODE_ENV=production` makes the web app, the worker, the pages service and the computer refuse the public development secrets (`DEV_SECRETS` in `packages/domain/src/server/secrets.ts`), makes the pages service and the web app require `PAGES_SECRET`, and turns `WATCH_ALLOW_PRIVATE_URLS` off by default.
Set it on every service, the computer included; local Compose leaves it unset for the computer.
`PORT` is read by the pages service only.
The web app and the worker use their own port settings.

## Test and tooling variables

None of these belong in `.env.example`, and none matter to a running deployment.
They are read by test suites, test scripts and developer tooling.
Most suites also read the runtime variables above, with the same development defaults.

<Callout kind="warning">
  Variables marked "real service" make a test reach something outside your machine. Everything else
  stays on localhost or in a disposable container.
</Callout>

### Integration tests

Run with `pnpm test:integration`.

| Variable                        | Read by                                                        | Purpose                                                                                                                                                                                             |
| ------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TEST_DATABASE_URL`             | `packages/db/src/testing.ts`, `scripts/test/*.sh`, CI          | The Postgres server each `*.integration.test.ts` suite creates its own database on. When unset, the suites skip; on CI, unset is an error. `scripts/test/pg.sh` starts a throwaway one with Docker. |
| `TEST_PG_DATABASE`              | `scripts/test/pg.sh`                                           | The database name on that throwaway server. Default `postgres`. The memory suite uses `openbot_memory_test`.                                                                                        |
| `OWNER_RESET_TEST_DATABASE_URL` | `scripts/ops/owner-reset-password.test.mjs`                    | The database for the owner password reset test. `pnpm test:owner-reset` sets it from `TEST_DATABASE_URL`, which must end in `openbot_owner_reset_test`.                                             |
| `CI`                            | `packages/db/src/testing.ts`, `apps/site/playwright.config.ts` | Set by CI. Makes a missing `TEST_DATABASE_URL` an error, and stops the site e2e from reusing running servers.                                                                                       |
| `UPDATE_VECTORS`                | `packages/egress/src/vectors.test.ts`                          | Set to `1` (`pnpm --filter @open-bot/egress vectors`) to rewrite the egress test vectors instead of checking them                                                                                   |

### End-to-end tests

Run with `pnpm e2e` against a running stack (`playwright.config.ts`, `e2e/`).
The specs write to the stack's database and computer directly, so they need the whole stack named, with no defaults (`e2e/stack.ts`): either `E2E_STACK=dev` alone, or all of `E2E_BASE_URL`, `DATABASE_URL`, `WORKER_URL` and `BOTD_URL`.
They also read `WORKER_SECRET` and `BOTD_TOKEN`, with the development defaults.
Point them at a development or throwaway stack only.
Tests tagged `@agent` run real teammates on the computer and use your ChatGPT plan.

| Variable                                   | Read by                                        | Purpose                                                                                                                                                      |
| ------------------------------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `E2E_EMAIL`, `E2E_PASSWORD`                | `e2e/helpers.ts`, `scripts/test/mobile-ui.mjs` | The owner account to sign in with. `E2E_EMAIL` falls back to `OWNER_EMAIL`.                                                                                  |
| `E2E_STACK=dev`                            | `e2e/stack.ts`                                 | Run against the local development stack: the web app on `localhost:3000`, its database, worker and computer. Leave the four variables below unset.           |
| `E2E_BASE_URL`                             | `e2e/stack.ts`, `scripts/test/mobile-ui.mjs`   | The web app. Required unless `E2E_STACK=dev`. The mobile UI test defaults to `http://localhost:3000`.                                                        |
| `DATABASE_URL`, `WORKER_URL`, `BOTD_URL`   | `e2e/stack.ts`                                 | The stack's database (with its host and database name), worker and computer. Required unless `E2E_STACK=dev`.                                                |
| `E2E_TELEGRAM=1`                           | `e2e/telegram.spec.ts`                         | Run the Telegram tests. Start the worker with `TELEGRAM_API_BASE_URL` pointed at the mock.                                                                   |
| `E2E_PLAN_REHEARSAL=1`                     | `e2e/fallback-rehearsal.spec.ts`               | Run the plan fallback rehearsal. Start the worker with `OPEN_BOT_PLAN_BASE_URL` pointed at a server that reports a usage limit.                              |
| `E2E_ACCOUNTS=1`                           | `e2e/accounts.spec.ts`                         | Run the Gmail, Calendar and Notion tests. Start the web app and the worker with `GOOGLE_BASE_URL` and `NOTION_MCP_URL` pointed at the stand-in on port 4796. |
| `E2E_TRACKER_MCP_URL`, `E2E_TRACKER_TOKEN` | `e2e/job-scout.spec.ts`                        | Real service: a real Application tracker's MCP address and a token for a test user. The full Job Scout test skips without both.                              |
