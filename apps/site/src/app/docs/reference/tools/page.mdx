# Teammate tools

Besides Codex's built-in shell, file and web search tools, every teammate has the 52 dynamic tools below, plus 28 tools for [your accounts](#your-accounts) in three namespaces.
They are defined in `apps/worker/src/tools/definitions.ts` and handled in `apps/worker/src/tools/handlers.ts`, with the teammate tools in `apps/worker/src/tools/bots.ts` and the account tools in `apps/worker/src/accounts/`.

## How tools are served

- Every thread gets every tool, so a teammate behaves the same in any chat.
- The worker validates arguments against each tool's JSON schema, and returns readable errors the model can act on.
- Each call becomes a timeline item, recorded by the handler with more detail than Codex's generic item.
- Before every call, the handler checks that the teammate's memory hasn't changed since the run started. If it has, the turn is interrupted.
- Tool definitions and the developer instructions are versioned together with `TOOLS_VERSION` (currently 19). Changing either requires a bump, which starts fresh threads.

Arguments marked with `?` are optional.
**Helpers** are swarm helper runs, which can't use the tools marked "no".

## Desktop

Every desktop tool acts on the teammate's own screen (or a helper's own screen), takes the screen's lease, and returns a JPEG screenshot taken after the action.
Coordinates are in pixels on the 1280x800 screen.
They all fail with `user_has_control` while you hold the screen.

| Tool                 | Arguments                        | Does                                                                                       | Helpers |
| -------------------- | -------------------------------- | ------------------------------------------------------------------------------------------ | ------- |
| `desktop_screenshot` |                                  | Looks at the screen                                                                        | yes     |
| `desktop_click`      | `x`, `y`, `button?`, `clicks?`   | Clicks at a point (left, right or middle, up to a triple click)                            | yes     |
| `desktop_move`       | `x`, `y`                         | Moves the pointer, for hover menus                                                         | yes     |
| `desktop_drag`       | `fromX`, `fromY`, `toX`, `toY`   | Drags with the left button                                                                 | yes     |
| `desktop_scroll`     | `x`, `y`, `direction`, `amount?` | Scrolls over a point                                                                       | yes     |
| `desktop_type`       | `text`                           | Types into whatever has keyboard focus                                                     | yes     |
| `desktop_key`        | `keys`                           | Presses keys or shortcuts, like `ctrl+l` or `Tab Tab Enter`                                | yes     |
| `desktop_open_url`   | `url`                            | Opens a URL in a new browser tab, starting the browser if needed                           | yes     |
| `desktop_wait`       | `seconds`                        | Waits for the screen to settle                                                             | yes     |
| `browser_read_page`  | `selector?`                      | Returns the front page's address, title, visible text and up to 300 links, as outside data | yes     |

## Your accounts

These act in your own [Gmail, Google Calendar and Notion](/docs/flows/accounts).
They are in the `gmail`, `calendar` and `notion` namespaces, so a call reads like `gmail.search`, and they load on demand (`deferLoading`): a teammate looks them up when a task needs them.

- Every thread has them. The worker checks on every call that the connection is on, shared with the teammate, allows the tool, and was granted it at sign-in.
- Every tool takes `account?`, the email address or Notion workspace to use, when you connected several of a kind.
- Reads come back as outside data, and the first one makes the rest of the run [ask before sending anything](/docs/flows/accounts#mail-events-and-pages-are-not-instructions).
- **Asks** says when a call needs you: by the teammate's autonomy, or always for anything others see. See [What asks you first](/docs/flows/accounts#what-asks-you-first).
- Helpers can use the reads only.

## Codex's built-in tools

Codex also gives every teammate:

- a **shell**, running as the `bot` user in its workspace, with streamed output;
- **file edits** as patches;
- **web search**;
- **plans**, which show as a checklist in the timeline;
- **MCP tools** from the teammate's [connections](/docs/flows/skills-and-connections#connections).

For teammates on "Ask before every command", the shell and file edits need your approval through Codex's own approval requests.
